# M4b 报告：纹理网格形变

- 日期：2026-11-07；分支 `morph-master`（未提交）
- 门禁（PLAN M4b）：纹理跟着形状走，而不是淡入淡出；记录翻折和裂缝

## 1. 做法

| 步骤 | 实现（`vector/mesh.ts`，纯函数） |
| --- | --- |
| 边界 | 用矢量轨道的对应关系匹配 A、B 两部件的轮廓，取 K = 96 个共享样点（第 k 个点在 A 和 B 上一一对应） |
| 内部 | 在 A 部件内铺六边形排布的点，和边界点一起做 Bowyer–Watson Delaunay 三角剖分；丢掉质心在外的三角形 |
| 带动 | 每个内部顶点记录相对 A 边界的**均值坐标**（mean-value coordinates，凹多边形也成立）。任意时刻的边界都能带动整张网：顶点 = Σ wₖ·边界ₜ[k]。同一组权重套在 B 的边界上，就得到该顶点在 B 图上的纹理坐标 |
| 渲染 | `drawMeshTexture`：每个三角形用自己的仿射变换贴图，目标三角形外扩 0.7 px，避免接缝。A 的纹理正向形变到当前形状，B 的纹理反向形变到**同一个**形状，对齐之后再融合 |
| 自检 | `flips(mesh, pos)`：统计相对静止网格方向翻转或塌缩的三角形 |

## 2. Demo：MM15 `lab/mm-mesh-warp`

用户的两张锦鲤候选图（v1、v2），部件相同（身体、尾、背鳍、胸鳍、眼），形状、姿态和斑纹都不同。

- 上：只做交叉淡化。50% 时有两只眼、两套背鳍、两条尾巴（双重曝光）。
- 下：逐部件网格形变 + 融合。每一帧都只有一条鱼，斑纹在同一条鱼身上从一种过渡到另一种。
- A → B → A 往返，可以双向拖动。

## 3. 门禁结果

| 门禁 | 结果 |
| --- | --- |
| 纹理随形状移动，而不是淡入淡出 | ✅ 逐帧看过 1.8、2.4、3.0 s：下栏始终是单一一条鱼，上栏的双重曝光作为对照 |
| 记录翻折 | 全部 5 个部件共 2579 个三角形，翻折峰值 **6 个（0.23%）**，都在身体的须和背鳍后缘这类又细又凹的边界上。**反直觉的发现**：边界采样越密（K = 160、240）翻折越多。原因不是内部分辨率，而是两张画在这些凹处的轮廓走向本身就不同。保留 K = 96 |
| 记录裂缝 | 共享顶点的网格本身没有裂缝；三角形之间靠外扩 0.7 px 消除发丝缝。剩一处：尾巴根部有一条细线，来自源图拆层时抗锯齿边缘的重叠，静止时也存在，不是形变造成的 |

## 4. 验证

- 测试 80 项全部通过，新增 4 项：Delaunay 覆盖凸包；均值坐标在凹多边形里也能精确重现线性函数；边界做仿射运动时内部精确跟随仿射且零翻折；B 侧纹理坐标与边界一一对应。
- `pops.mjs`：MM15 无突变；`check:visual` PASS；离线文件 `gallery/mm-mesh-warp.html`。

## 5. 同时修了 MM14 网格翻牌（用户反馈）

**反馈**：现在翻牌太连贯，一竖列的牌几乎一体，看起来像竖向的百叶窗。

**原因**：波从左边中点出发，同一列的牌到起点的距离几乎相同，所以同时翻。

**修复**：网格模式下，波从左上角沿对角线推进，每块牌再加 30% 的独立时间抖动；百叶窗模式保持整齐。修复后每块牌都是各自翻转的卡片。`photo.md` 写入了这条规则。

## 6. 限制

- 网格形变只适合**同类**主体（两条锦鲤、两张脸）。差异很大的形状（雨伞 → 章鱼）内部映射会折叠，应该用粒子或碎裂。
- 每帧要画约 2600 个三角形 × 2 层纹理，在 GPU 浏览器里流畅；软件渲染会慢。
- 边界目前是线性插值。形状差别大的部件可以换成 intrinsic 插值（M1），尚未接入。
