# M5 报告：3D 模型（glTF）

- 日期：2026-11-07；分支 `morph-master`（未提交）
- 门禁（PLAN M5）：60fps 预览（GPU）；首尾是完整模型

## 1. 素材

工作区里**没有任何 3D 模型**。为了不下载第三方模型，新写了 `tools/make-glb.ts`：一个最小的 GLB 2.0 写入器，用 three 的几何体生成原创的程序化模型，每个部件是一个带名字（部件 id）和基础色材质的节点。场景通过 three 的 `GLTFLoader` 加载，走的是真实的 glTF 读取流程。

| 文件 | 部件 |
| --- | --- |
| `fixtures/s3/rocket.glb` | nose、body、window、fin_a/b/c、flame |
| `fixtures/s3/lighthouse.glb` | cap、lamp、gallery、tower、stripe_1/2、door、base |
| `planet.glb` | 备用 |

**如实说明**：真实世界的 glTF（贴图、蒙皮、一个节点含多个图元）尚未测试。

## 2. 机制

| 文件 | 内容 |
| --- | --- |
| `vector/cloud.ts`（纯函数） | 按面积加权、带种子的表面采样；**每个顶点带一个时间**（A 上是离开时间，B 上是落地时间），采样点取所在三角形顶点时间的重心插值，和片元着色器的插值完全一致；3D 值噪声；按各自包围盒做 Morton（Z 序）配对 |
| `renderers/morph3d.ts` | `loadGlbParts`（烘焙到世界坐标，读取材质颜色）；`Morph3D`：和 2D 相同的部件映射约定（每个部件恰好一个去向；1→1、分裂、融合、新生、消失；每条映射有自己的时间窗）；GPU 点云（3.6 万点，二次 Bézier 飞行，颜色从 A 过渡到 B）；A、B 网格的着色器按插值时间丢弃片元（局部交接）；`style: "exploded"` 让部件以实体形式沿径向飞出、在外面变成点云重塑、新部件再以实体形式飞回 |
| `vite.config.ts`、`glb.d.ts` | 把 `.glb` 注册为资源，`?inline` 可以内嵌进离线 HTML |

## 3. Demo

- **MM16 点云**：火箭 → 灯塔。火箭先轻微震动（起因），从鼻锥往下溶解成带各部件颜色的点；点盘旋后从底座向上搭成灯塔。映射：鼻锥 → 灯罩，箭身 → 塔身，火焰 → 灯（火变成光），窗户圆环 → 观景台，三片尾翼 → 底座（融合），条纹和门从塔身中新生。
- **MM17 爆炸重组**：同一份映射。每个部件在自己的时间窗里以实体形式飞出（像爆炸图），在外面变成新部件，再飞回组装。顺序是：地基先就位，最后是条纹和门。

## 5. 过程中发现并修好的问题

1. **溶解出的洞里是黑点**：单面网格溶解后，从洞里看到的是没有光照的背面，像脏点。→ 改为双面材质，并加上“余烬边”：刚溶解或刚凝结的片元发暖光，溶解前缘读起来像燃烧的边。
2. **第一版爆炸重组不像爆炸图**：网格原地溶解，点云只是稍微飘开。→ 重写为实体飞出 → 在外面重塑 → 实体飞回（`style: "exploded"`）。
3. **爆炸位置出现点状残影**：大小为 0 的点在某些 GPU 上仍会画一个像素。→ 静止的点移出裁剪空间。
4. **观景台整圈闪一下**：爆炸部件的前缘只有约 0.03，余烬光却持续 0.035，整个部件在一帧内同时发光。→ 余烬宽度限制为前缘宽度的四分之一，爆炸部件不加余烬光。`pops.mjs` 测到了这个问题。
5. **箭身溶解太快，像一下顿挫**：6% 的展开在约 0.17 s 内扫过整个箭身。→ 爆炸部件的展开改为 12%。
6. **dev 服务器对 `.glb` 返回 500**：服务器是在新增 Vite 配置之前启动的。→ 重启后正常。

## 6. 限制

- 点使用部件的基础色，模型贴图还没有带进点云。
- 只用绑定姿态，忽略骨骼动画。
- 点的透明混合没有排序（`depthWrite: false`）；云很密时远处的点可能叠在近处之上，目前没有观察到明显问题。
