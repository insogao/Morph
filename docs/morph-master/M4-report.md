## 2. 门禁

| 门禁 | 结果 |
| --- | --- |
| 轮廓误差小于 1–2 px | ✅ 用合成的半径 100 圆盘实测：顶点最大误差 0.17 px，平均 0.13 px；简化后相邻顶点之间的弦高约 0.6 px，整体小于 1 px |
| 粒子颜色取自原图 | ✅ 每个格的颜色就是原图块的 alpha 加权平均色（测试）；飞行中从 A 格颜色过渡到 B 格颜色 |
| 首尾帧就是原图 | ✅ 第一个粒子出发之前、最后一个落地之后，直接绘制原图；中间每个格都在自己的粒子出发或落地的那一刻切换 |
| 不是交叉淡化 | ✅ 粒子按格交接；碎片靠正反两面翻转；翻牌靠正反面；墨晕是空间扩展 |

- 测试：76 项全部通过（新增 5 项）。

## 4. 过程中发现并修好的问题

1. **碎片的空白面显示成灰色多边形**：边缘变暗原来是在整个碎片多边形上填半透明黑色，透明的部分也被涂灰，看起来像碎屑。→ 改用画布的 `brightness` 滤镜，只作用在碎片自身的像素上。
2. **MM14 交接处的突变**：`pops.mjs` 在 4.017 s 测到一次突变，变化量是邻近帧的 193 倍。原因是画框比例（880 × 500）和裁出的画（16:10，即 880 × 550）不一致，翻牌网格比后面绘制的整张图少显示了一条。→ 画框改为严格 16:10；`photo.md` 写入“A、B 同一比例、同一画框”。

## 5. 如实说明

- **项目里没有真实照片**。“照片路线”是用贴在纸色底上的画测试的，所以验证的是机制，不是照片上的观感。用户提供照片后需要再测一次。
- 像素粒子不会让纹理在轮廓内部拉伸，纹理是随色块一起移动的。“花纹跟着形状变形”需要 M4b 的网格形变。
- 粒子数量和 `step` 有关（默认 5 px，约 4000 格）。粒子少，画面显得粗糙；粒子多，帧率下降。

## M4.1：根据反馈修订（2026-11-07）

| 反馈 | 原因 | 修改 |
| --- | --- | --- |
| 粒子化结束后，章鱼身上出现明显的矩形 | 落地顺序跟着 Hilbert 配对走：配对相邻的格同时落地，B 上整块方形区域一起完成，留下直线边 | `schedule` 新增落地扫描 `landOrigin`，从一个有意义的点出发（这里是章鱼的头），加上平滑噪声，和配对无关。现在章鱼从头向外长出来，触手尖最后到位，没有直线边 |
| 变化后章鱼抖动两下，很违和 | 我加的“收尾动作”没有任何起因 | 删掉；成品静止停留。指引写入“不要加没有动机的收尾动作” |
| 碎裂时的笔画效果很违和：“要么做好，要么直接碎” | 画的是随意的放射状线条，和真实的碎裂位置无关 | 做好：裂纹就是真实的碎片边缘。从敲击点沿 Voronoi 边向外蔓延，刻痕式（深色线 + 浅色边），按图像 alpha 遮罩不越界，并且留在每一片上直到它飞起；碎片正好沿裂纹分开。同时删掉了圆环和假裂纹 |
| 喜欢网格翻牌，也可能有人喜欢百叶窗 | — | `tileFlip` 新增 `mode: "blinds"`（整宽横条、绕水平轴翻转）；MM14 新增第三段：燕子 → 锦鲤（百叶窗）。`photo.md` 写明网格是默认首选，百叶窗作为备选 |
| （检查时发现）静止的格 / 条之间有发丝缝 | 每格单独裁剪绘制，抗锯齿留下了缝 | 静止的格合并成一张裁剪图绘制，只有运动中的格单独画 |

验证：测试 76 项全部通过；MM12、MM13 无突变；MM14 剩一处是静止片段之后运动的第一帧（不是跳变）。三个场景 `check:visual` PASS，离线 HTML 已更新。
